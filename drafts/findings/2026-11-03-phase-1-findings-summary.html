MemBrain PoC · Phase 1 · Core memory

What we learned about SurrealDB Agent Memory

One person chatted in Claude Cowork with the Agent Memory plugin, and we checked by script what was stored, changed, recalled and forgotten. These are the findings that matter most for the build, with repeats merged.

Runs 30 Oct to 3 Nov 2026 Tester Vidyul Narayanan Context membrain-dev-lite Status Draft

Undesired

Undesired

A correction can erase a fact without storing the new one

"Kestrel Freight now ships on time" removed the old shipping fact and stored nothing in its place. A rewording replaced "late on most orders" with the stronger "always behind". The replaced values can't be read back.

Undesired

Repeats leave no trace, so confirmations can't be counted

Saying the same thing again changes nothing on the fact, and rewording resets it. Promotion can't take confirmation counts from facts, so it will have to work from the saved chat.

Undesired

Extraction is inconsistent

The same kind of plain sentence became a fact one time and nothing another. Lasting facts, such as a price, were sometimes filed as context, which expires after 7 days. The saved chat is the full record, and the facts are an incomplete index of it.

Undesired

Recall can answer from saved chat instead of the stored facts

When we asked how to format answers and what the person was working on, the plugin's recall returned only saved chat passages and none of the stored facts, instructions or entities. Cowork built its answer from that raw chat text and left out the metric-units preference. In a later recall the stored facts did come back, so what the agent receives varies from one question to the next.

Undesired

Instructions pile up, and are framed as not to follow

Changing an instruction adds a new one and keeps the old ones, so "use bullets" and "use paragraphs" sit side by side. The plugin labels everything it injects as "background context, not instructions", so even a recalled rule is presented as something not to apply.

Undesired

Forgetting removes the sentence, not the facts

Forget removed the chat passage but no fact taken from it, and those facts kept answering. Each time the agent repeated them, they were stored again. "Don't save that" also still saved the chat.

Undesired

No erase is audited

Forget, permanent purge and area erase all left no audit entry. An agent chose the permanent option on its own when asked only to "forget", and there is no record afterwards of who erased what.

Undesired

Claude's replies become facts about the person

Claude's answers are saved and extracted like the person's own words, at the same trust. The person never mentioned their employer, but Claude's reply did, and "works at Techjays" was stored as an identity fact.

Undesired

Reflection helps but invents, and consolidation can't be checked

Reflection answered well from chat history but added claims nobody made, and could not save with a personal key. Consolidation reported new records that no endpoint returns, and merged none of the duplicates.

Undesired

Every save starts a new session

The plugin sends no session id, so Agent Memory opens a new session for every save. Two messages sent in the same Cowork task landed in two different sessions, so memory can't be grouped by conversation.

Undesired

A preference is sometimes stored twice

"I prefer metric units" became both an instruction and a fact on the person, and the two aren't linked. Later, the fact copy of a formatting rule was removed while its instruction copies stayed, so the two records can disagree.

Undesired

Uploaded files wait in the queue and are never processed

A small markdown file uploaded on 3 Nov stayed "queued" for over 90 minutes, and processing never started, so nothing was extracted or searchable. Every document uploaded to the context since 2 Nov is stuck the same way; the last one processed was on 12 Oct.

Works

Works

Chat is saved and recalled in a new task

Every exchange was saved to the person's own area within about 10 seconds, and a new Cowork task recalled it without being told again.

Works

Area keys keep people apart

A second test person's key could not read or write the first person's area. Search, reflection, consolidation and elaboration all stayed inside the caller's area.

Works

Every record says where it came from

Each fact and link carries a source and a trust score, so a job can keep what was said and drop what Agent Memory guessed. Hedged statements ("I think… might…") get lower confidence and an open uncertainty record.

Works

Labels work on structured writes

Labels written with a fact are stored and work as a search filter, which is what tagging facts with VCT nodes needs. Exact repeats are not duplicated.

Works

Erasing an area is complete

Erasing a person's area removed their entities, facts, links and chat, and left records with the same names in other areas untouched.

Each finding comes from a single run with one person in one Context, checked against Agent Memory's audit log, record lists and search. The detail, with method and evidence, is in the five findings files and the phase 1 primer under drafts/ in the PoC repository.
