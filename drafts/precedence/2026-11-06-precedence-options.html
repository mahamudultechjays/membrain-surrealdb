Layer precedence and promotion on Agent Memory

Proof of conceptDate 6 November 2026Layers org · team · personal
The question
When org, team and personal scopes hold different values for the same thing, which one should an answer use?
What we found
In our tests Agent Memory never compared facts across scopes, and it has no setting to rank one scope above another. Any order we add on top must not hold trust outside Agent Memory, which we agreed not to do.

1What testing showed

We ran two tests on fresh scopes: three scopes, one note each, with conflicting values in each layer.

FindingEvidence
Reflect on one scope does not see the other layers.Asked whether the records disagree, every single-scope Reflect said they agree, in both tests.
Reflect across scopes finds the conflict, but picks no winner.It named every conflicting value, and said the answer “hinges on which guideline takes precedence”.
Reflect cannot tell which layer holds which value.Its evidence carries no scope. When the notes did not name their layer, it invented a timeline (“lead time dropped from 28 to 21 to 14 days”) for notes stored the same day.
Consolidate and Elaborate never compare across scopes.Both run inside one scope. Consolidate stored only facts with proof 2 or more (1 of 23 reported across both tests).

What Agent Memory offers natively

  • No scope weighting. Recall (/query) takes lens, labels, mode, k and asOf. A lens narrows what is read; nothing ranks one scope above another.
  • Decay by category. A daily pass multiplies importance by 0.95 for context, 0.995 for knowledge and 1 for identity. Context expires after 7 days.

2Precedence options

Each option is judged against one agreed rule: we may build layers on top, but we must not represent or manage trust in our own system.

Design premise. Team and org layers hold only promoted rules, each verified before it got there. Personal layers hold everything a person captures. So the real question is when a verified rule should outrank a person’s own note.

What our tests cover. Both tests stored raw notes in org and team, not promoted rules. They show how Agent Memory treats conflicting facts across scopes, not how a verified rule meets a personal note.

The fair-search variant of C comes from the earlier layers-and-promotion spec (28 October). That spec ranked answers org first (option A); it was written before the rule above was agreed.

A

Fixed layer order: org, then team, then personal

Partly crosses the line

Read each layer, and when values differ, the broader layer wins.

For

  • Simple to explain and predictable.
  • Team and org hold only verified rules, so the broader layer wins for a reason people agreed on.

Against

  • A rule still wins when a personal note is far more relevant to the question.
  • Re-ranks after Agent Memory has already fused and ranked results.
  • The order itself lives in our code.
B

Relevance first, layer order only to break ties

Partly crosses the line

Keep Agent Memory’s ranking. Apply the layer order only when two layers answer the same point and both match well.

For

  • A 90% personal match is not overruled by a rule that matches at 10%.
  • A verified rule still wins when both match well.
  • Leaves most answers to Agent Memory.

Against

  • Needs one recall per layer, since hits carry no scope.
  • Scores from separate recalls may not be comparable.
  • “Far more relevant” needs a threshold we set.
  • Deciding “same point” is hard when keys differ.
C

Show every layer, decide nothing

Keeps trust in Agent Memory

Answer from all readable scopes, label each result with its layer, and flag disagreements for the user.

Fair-search variant: query each layer in parallel with a fixed share of results, for example 10 personal, 10 team and 20 org, so no layer crowds out the others.

For

  • No trust logic on our side.
  • Nothing is hidden, so a user sees when policy and practice differ.

Against

  • The user resolves conflicts.
  • Labels need one recall per layer, or a layer label written with each fact.
D

Targeted Reflect across scopes, ahead of time

Detects, does not resolve

For topics where conflicts are expected, run Reflect across the layers in advance to find disagreements.

For

  • The only Agent Memory feature that saw cross-layer conflicts in our tests.

Against

  • We must know which topics to check.
  • About 10 to 40 seconds and one model call per question.
  • Picks no winner, and may invent an order of events.

Considered and set aside

A confidence score per scope. Agent Memory has no per-scope weight, and decay could push a high-trust layer below a lower one over time.

Our proposal

  1. V1 works from the personal layer. Each user’s answers come from their own scope, with team and org rules shown beside them and labelled by layer (option C).
  2. Nothing is overridden automatically. When a personal note disagrees with a verified rule, the user sees both.
  3. Revisit A or B once real promoted rules exist. Then we can test how a verified rule meets a personal note, which our tests did not cover.

3Promotion: moving shared knowledge up a layer

Promotion means turning something many people hold into one team or org fact. Agent Memory has no promotion feature, so each route below is ours.

The ladder from the earlier spec

Org ruleThe org step works the same way, one level up.
org admin approves
Team ruleWritten to the team layer only when a team admin approves.
team score ≥ 3 → shown to the team admin
Personal ruleAt the holder’s own score of 1.75: stated once, confirmed twice more.

Each person’s support for a fact is weighted, so that nobody can push a fact up alone. One person adds at most about 2, so a team score of 3 always needs at least two people.

EventAdds to the score
A person’s first statement of the fact1
That person’s 2nd, 3rd, 4th confirmation0.5, 0.25, 0.125…
A different person’s first statement1
A person’s first contradiction, then repeats−1, −0.5, −0.25…

Routes compared

RouteHow it worksMain trade-off
Counter ladderScore support per person as above; show candidates at 3 to an admin.Needs every fact under a standard name and key, so one fact is counted once.
Similarity across personal scopesFind facts about 90% alike in several people’s scopes, merge them into one new fact, and write it to the team layer.Groups facts by their text, so different keys do not matter. Says nothing about how many people agree.
Impact on VCT goalsScore a fact by how many VCT nodes and goals it connects to and how often it is recalled. Promote the highest scores.Depends on the VCT tagging, which is still at design stage.
Admin approvalAn admin approves each candidate before anything is written.Slower, but nothing is promoted automatically.

A likely combination: similarity to group facts that mean the same thing, the counter with its two-person minimum to score them, and admin approval to write the result. The VCT impact score can then order the candidate list.

Promoting what was never extracted

Agent Memory extracts few facts on purpose. The rest stays in stored passages, the raw notes and chat turns, which recall can still find. A promotion system that only looks at facts misses most of what people say.

RouteHow it worksWhere it stands
Match passages, not just factsRun the similarity check over stored passages in personal scopes. When several people’s passages say the same thing, put one fact on the candidate list.Untested. Recall already returns passages with a match score, so this needs no new Agent Memory feature.
Let interest surface factsFor topics many people ask about, run Reflect with saving on, so its answer is written as a fact that can then be scored.Unproven. In both our tests, Reflect with saving on wrote nothing.

What our tests add

  • Consolidate cannot replace the counter. It works within one scope and stored only facts with proof 2 or more.
  • Standard naming, or matching by text, is required. The same term was stored under different keys in each scope, such as promotional_discount_cap and max_promotional_discount.
  • Only extracted facts can be promoted. Extraction is sparse, so much knowledge stays in passages and is never a fact.
  • A promoted fact is a new write. Written as a triple, we choose its category (knowledge or identity), so it does not expire like context.
